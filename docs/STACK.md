# Stack

Reuse what worked on Leash. Nothing new unless it saves a day.

| Layer | Choice | Why |
|---|---|---|
| Language | Python 3.11 | Lambda runtime; Leash already uses it. |
| Scorer | Pure Python (`statistics`, `math`), no pandas or numpy | The data is small (about 50 stations × 672 hours). No layer to build, fast cold start, and the same code runs in pytest and in Lambda. The spike's pandas code is a reference, not a dependency. |
| Infra as code | AWS SAM (`template.yaml`) | Copied from Leash. `sam deploy` once with `--guided`, then `make deploy`. |
| Schedule | EventBridge `rate(1 hour)` -> ingest Lambda | #3 |
| Secrets | SSM SecureString `/ground-truth/openaq-key` | #1. Never in the repo. |
| Storage + hosting | One S3 bucket (`index.html`, `assets/`, `data/`) behind CloudFront | #2. Falls back to the S3 website endpoint if CloudFront is blocked on the plan. |
| Data in | OpenAQ API v3 `/sensors/{id}/measurements` (raw 15-min readings, grouped into IST hours by our code) + public archive `s3://openaq-data-archive` (backfill, us-east-1) | The archive is about 4 days behind, so the API covers the gap. |
| Front end | Vanilla HTML/CSS/JS, no build step | Own design system in `site/theme.css`, visually referenced from neatlogs.com: light mode only: silver fog hero, product window, Geist + Geist Mono. One `index.html`, one `app.js`, one `theme.css`. |
| Map | three.js 0.160 (vendored from npm), our own 3D scene | Delhi in fog built from our own ward data (DataMeet, CC BY-SA 2.5 IN): city blocks, Qutub Minar, India Gate and the Lotus Temple, a mast per monitor with a column as tall as its PM2.5 and smog clouds, drifting dust. No tile server. Click for full-screen 3D. |
| Chart | Chart.js 4.4.1 (vendored from npm) | Hour-of-day gap: last 7 vs 28 days, 11-17 window shaded, table view. |
| Tests | pytest. Planted-anomaly test + physics unit tests + JSON contract test | Run in CI on every PR. |
| CI/CD | GitHub Actions: `pytest` on PR; `sam deploy` on merge to main (OIDC role, no long-lived keys) | Copied from Leash. |
| Video | Hyperframes (HTML -> video) + edge-tts voice-over | Scripted from day 1 so it isn't rushed on Sunday. |

## JSON contract (front end <-> Lambda)

A real sample generated by the scorer from the archive (28 days to 4 Oct 2026) is in `sample/data/`. Build against that, not hand-written mocks.

`data/latest.json`
```json
{
  "generated_at": "2026-10-08T14:25:04+05:30",
  "data_through": "2026-10-04T17:00:00+05:30",
  "stations": [
    {"id": 8235, "name": "Jahangirpuri, Delhi", "lat": 28.73282, "lon": 77.170633, "region": "Delhi",
     "status": "flag", "status_since": "2026-10-04T12",
     "checks": {
       "physics":    {"status": "ok",   "fail_pct": 0.0, "detail": "0.0% of the last 7 days' hours report impossible values (...)."},
       "neighbours": {"status": "ok",   "z": -0.24, "detail": "Against its neighbours, its daytime PM10 reads 6% lower than at night (3% lower is typical for a station like it)."},
       "history":    {"status": "flag", "z": 3.73, "param": "relativehumidity", "detail": "Its daytime humidity, against its neighbours, reads 5.2 pts higher than over its previous 3 weeks."}
     },
     "operator": "DPCC",
     "latest": {"pm10": 237.75, "pm25": 41.5, "no2": 36.88, "co": 1.53, "relativehumidity": 48.75},
     "neighbours_latest": {"pm25": 43.62, "pm10": 179.75},
     "last_reading": "2026-10-04T17:00:00+05:30",
     "band": "Poor", "neighbours_band": "Moderate"}
  ]
}
```
`latest` values can be `null`. `z`, `fail_pct` and `param` are absent when a check is `nodata`. `region` is `Delhi` or `NCR`.

- `neighbours_latest`: the median of the 4 nearest monitors' latest PM2.5 and PM10 (needs 2 of them), else `null`.
- `last_reading`: the IST hour of the monitor's newest PM2.5 or PM10 value in the 28 days, or `null`.
- **Silent monitors:** with no PM reading in the last 3 hours, `status` is `nodata` whatever the checks say, and the station gets a `detail`, e.g. `"No reading since 07:00 on 8 Oct."`. Its `checks` stay as they were. `detail` is present only then.
- `band` and `neighbours_band`: the CPCB AQI band (`Good`, `Satisfactory`, `Moderate`, `Poor`, `Very poor`, `Severe`) of the 24-hour average PM2.5 and PM10, the worse of the two, for this monitor and for the median of its neighbours' averages. `null` with fewer than 16 hours of data. The site shows `band` when the monitor agrees with its neighbours and `neighbours_band` otherwise.
- `operator` is the agency code (`CPCB`, `DPCC`, `HSPCB`, `UPPCB`, `IMD`, `IITM`) from `stations.tsv`; `null` for any station where it could not be determined. Full names, official dashboard links, and public grievance/complaint page URLs for each agency are in `src/operators.json`.

`data/stations/<id>.json`
```json
{"id": 8235, "name": "Jahangirpuri, Delhi", "neighbours": [5541, 8915, 8917, 10831],
 "hour_profile":    {"pm10": [0.12, 0.10, "...24 values, index = IST hour, null if too few"], "pm25": [], "no2": [], "co": [], "relativehumidity": []},
 "hour_profile_7d": {"...": "same shape, last 7 days only"},
 "daily": [{"date": "2026-10-04", "d_pm10": -0.05, "d_pm25": -0.02, "d_no2": 0.2, "d_co": 0.01, "d_relativehumidity": 9.1, "physics_fail_pct": 0.0}],
 "recent_48h": {"hours": ["2026-10-02T18", "...48 IST hour keys..."], "pm25": [41.5, "...48 values, null if no reading..."], "neighbours_pm25": {"5541": [38.0, "..."], "...": "one array per neighbour id"}}}
```

`data/weather.json` (written by the same run, from Open-Meteo for the region's centre; the site shows `line` under the hero and drifts the 3D dust with the wind)
```json
{"fetched_at": "2026-10-08T22:00:00+00:00", "time": "2026-10-09T03:30", "wind_kmh": 5.0, "wind_from_deg": 139, "wind_from": "SE",
 "boundary_layer_m": 412, "temperature_c": 25.3, "humidity_pct": 81,
 "line": "Calm air tonight (wind 5 km/h) and the air is mixing only a few hundred metres up: pollution is building up across the city.",
 "source": "Open-Meteo"}
```
Any field but `source` can be `null`; the file can be missing (the site then shows no weather line).

`data/history.json` (kept by the same run: every day of the last 28 scored at 17:00 IST as the live check would have, the way `docs/VALIDATION.md` was made; incremental, so a run adds one day). The site shows a month strip in every station panel (`#235/history` opens it) and "since yesterday" under the live map.
```json
{"generated_at": "...", "score_hour": 17, "days": ["2026-09-12", "...", "2026-10-09"],
 "stations": {"235": [{"d": "2026-09-12", "s": "ok", "c": "oow"}]},
 "totals": [{"d": "2026-09-12", "ok": 36, "watch": 7, "flag": 5, "nodata": 4}],
 "changes": [{"id": 7005, "name": "Loni, Ghaziabad", "from": "ok", "to": "watch", "day": "2026-10-09"}]}
```
`s` is the day's status; `c` is the three checks, physics/neighbours/history, one letter each (o ok, w watch, f flag, n no data); `changes` is the newest day against the one before; `names` maps ids to names for the feed. `data/changes.xml` is the same month of changes as an Atom feed (every pair of consecutive days, newest first, linking to `#<id>/history`), written when the Lambda knows the site's URL (`SITE_URL`).

`data/fires.json` (written only when a NASA FIRMS key is in SSM: the last 24 h of VIIRS fire points in the region's fire box, the brightest 400 as `points` = [lat, lon, brightness, date, time])
```json
{"fetched_at": "...", "count": 312, "box": [73.5, 27.5, 79.5, 32.5], "centre": [28.62, 77.2], "bearing_deg": 318, "direction": "north-west",
 "distance_km": 210, "high_confidence": 201, "points": [[30.9, 75.8, 341.2, "2026-10-08", "0730"]],
 "line": "312 farm fires in the last 24 h, north-west of the city.", "source": "NASA FIRMS, VIIRS SNPP NRT"}
```

Status values are exactly `ok`, `watch`, `flag` or `nodata`. Gaps are natural-log ratios, except humidity, which is in percentage points.
